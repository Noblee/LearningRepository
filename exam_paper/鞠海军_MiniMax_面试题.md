### 题目 5：Golang 并发模型与内存管理

**提问：**

你的技术栈以 Golang 为主，请回答以下问题：

1. **GMP 调度模型**：请描述 Goroutine、M（Machine）、P（Processor）三者的关系。当一个 Goroutine 发生系统调用阻塞时，调度器是如何处理的？`GOMAXPROCS` 设置为 CPU 核数的 2 倍会发生什么？
2. **Channel 底层实现**：一个 buffered channel 的底层数据结构是什么？`select` 语句同时监听多个 channel 时，底层的选择机制是什么（是轮询还是随机）？
3. **内存逃逸分析**：什么情况下变量会从栈逃逸到堆？如何通过 `go build -gcflags="-m"` 分析逃逸？在你的项目中，是否做过内存逃逸优化？具体优化了什么？
4. **sync.Pool 的使用场景与陷阱**：你提到项目中用了对象池复用，`sync.Pool` 的 GC 回收策略是什么？在什么场景下 `sync.Pool` 反而会降低性能？

**考察点：**
- Go 语言底层原理掌握程度
- 并发编程能力
- 性能优化意识
- 与 MiniMax 关联：Golang 是主力开发语言之一

**参考评估要点：**
- GMP：阻塞时 M 与 P 解绑，P 找新的 M 或创建新 M；GOMAXPROCS 过大导致上下文切换增加
- Channel：hchan 结构体 + 环形缓冲区 + 互斥锁 + 等待队列；select 随机选择 ready case
- 逃逸：返回局部变量指针、interface{} 传参、闭包引用、slice/map 动态扩容
- sync.Pool：每次 GC 时清空 victim cache；对象初始化成本低时使用 Pool 反而增加锁竞争开销

### 题目 8：带 TTL 的 LRU Cache（中等难度）

**题目描述：**

设计一个带过期时间（TTL）的 LRU 缓存，支持以下操作：

```
type TTLLRUCache interface {
    // Get 获取 key 对应的 value，如果 key 不存在或已过期则返回 -1
    Get(key int) int

    // Put 插入或更新 key-value 对，并设置 TTL（秒）
    // 如果缓存已满，淘汰最近最少使用的未过期 key
    Put(key int, value int, ttl int)
}
```

**要求：**
- `Get` 和 `Put` 操作的平均时间复杂度为 O(1)
- 过期的 key 不能被 Get 到，且在空间不足时优先淘汰
- 请用 Golang 或 Java 实现

**考察点：** 双向链表 + 哈希表 + 时间戳管理，综合数据结构设计能力

**follow-up：** 如果要支持并发安全，你会如何加锁？分段锁（sharding）如何实现？

### 题目 10：DAG 任务调度器（难）

**题目描述：**

这道题与 AI Agent 的 Tool Calling 编排直接相关。给定一组任务及其依赖关系（构成 DAG），设计一个调度器：

```

- deps: [[1,0], [2,0], [3,1], [3,2], [4,3]]  // [a,b] 表示任务 a 依赖任务 b
```

**要求：**

**考察点：**
- 拓扑排序（BFS / Kahn 算法）
- DAG 并行调度（贪心 + BFS 分层）
- 与 MiniMax 关联：Agent 多 Tool 并行编排、LLM Post-Training Pipeline 调度

**follow-up：** 如果每个任务有预估执行时间，且不同的执行节点有不同的算力，如何做最优调度？（关联到 LLM 推理集群的调度问题）
